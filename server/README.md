# 自己部署 AI 日程接口

这个服务端模板供每位使用者单独部署。网页只填写自己的服务地址和访问码；模型密钥仅在自己的服务端环境变量中设置，不写进公开仓库或浏览器页面。

需要 Node.js 20 或更新版本，以及支持 `POST /chat/completions`、`response_format: {"type":"json_object"}` 的 OpenAI 兼容模型接口。服务端只处理日程草案，不保存任务正文或模型回复；当前网页仍使用浏览器本地存储保存已确认日程。

## 本地运行

在 `server` 目录设置环境变量后运行 `node server.mjs`。不要把真实密钥填入命令行历史、网页或 README。环境变量：

| 名称 | 用途 |
| --- | --- |
| `AI_API_KEY` | 自己的模型服务密钥，必填 |
| `AI_MODEL` | 该服务支持的模型名称，必填 |
| `AI_BASE_URL` | 兼容接口根地址，默认 `https://api.openai.com/v1/` |
| `APP_ACCESS_CODE` | 自己设置的独立访问码，必填；不要与模型密钥相同 |
| `ALLOWED_ORIGIN` | 网页的准确来源，例如本机 `http://localhost:4173`；GitHub Pages 示例 `https://用户名.github.io` |
| `PORT` | 服务监听端口，默认 `8787` |

本机网页预览可在站点根目录运行 `python3 -m http.server 4173`。在网页的“我的 AI 服务地址”填 `http://localhost:8787`，访问码填服务端配置的 `APP_ACCESS_CODE`，即可请求 AI 草案。本机地址仅用于本机；公开 GitHub Pages 网页需要自己部署 HTTPS 服务端并填其公网地址。

## 网页里的地址怎么填

“我的 AI 服务地址”填**自己部署的本项目服务端根地址**，不要填模型提供方的 API 地址，也不要填 GitHub Pages 网页地址。网页会自动在末尾加 `/api/plan-draft`。

| 场景 | 网页中填写 | 前提 |
| --- | --- | --- |
| 同一台电脑本地测试 | `http://localhost:8787` | 本项目服务端运行在 8787 端口；网页由 `http://localhost:4173` 打开 |
| 服务端已公开部署 | 例如 `https://planner-api.example.com` | 该域名实际指向自己部署的服务端，且已启用 HTTPS；此处只是格式示例，不是可直接使用的地址 |

“访问码”填服务端 `APP_ACCESS_CODE` 的值，不是 `AI_API_KEY`。服务端内部的 `AI_BASE_URL` 才填写模型提供方的兼容接口根地址；`AI_API_KEY` 和 `AI_MODEL` 也只在服务端配置。若还没有部署服务端，暂时没有可填写的公网服务地址，可以先用“本地拆分”。

## 公开部署边界

- 每位使用者部署自己的服务端和密钥，网页允许填写不同服务地址。不要将私人服务端开放成无访问码的匿名接口。
- `ALLOWED_ORIGIN` 限定允许调用的网页来源；访问码仍是必要的访问控制。服务端按来源 IP 每小时限制 30 次请求，适合单人试用，不等同正式多用户账号系统。
- 网页只保存服务地址；访问码只在当前页面内存中使用，刷新后需要重新填写。请求中的待办文字和当天固定事件会发送至使用者配置的服务端及其模型提供方。
- 当前没有完成真实模型联调、云端部署、持久化额度控制或账号隔离。不同兼容服务商对 JSON 模式的支持可能不同，需要按选定服务实际验证。

## 接口

`POST /api/plan-draft`，请求头包含 `x-app-access-code`，JSON 请求体包含 `text`、`date`、`fixedEvents`。返回 `items`（标题、分钟数、类型、是否估计）和 `notes`。网页先展示可编辑草案，由使用者把事项放入小时表并确认后才保存。

测试：在站点根目录运行 `node --test plan-text.test.cjs server/server.test.mjs`。测试使用模拟模型响应，不需要真实模型密钥。
